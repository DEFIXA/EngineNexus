============================================================
1. INTRODUCTION
============================================================

DEFIXAS ENGINE NEXUS is a Windows AI Integration Platform designed to bring supported AI providers, development tools, workspaces, integrations, system information, and game-development systems into one desktop application.

ENGINE NEXUS is designed to reduce the need to manage separate command-line windows, dependency checks, setup steps, and disconnected development tools manually.

The current public test release focuses on:

- Codex integration
- Nwiro integration support
- Unreal Engine integration support
- Guided first-run setup
- Automatic dependency readiness checks
- Automatic dependency installation where supported
- AI Work Room
- Workspace support
- Persistent application configuration
- Session restore
- System statistics and telemetry
- Integration and connection status
- Windows installation and uninstall support


============================================================
2. WHO ENGINE NEXUS IS FOR
============================================================

ENGINE NEXUS is intended for developers and creators who work with AI-assisted development tools, game engines, automation systems, and connected development workflows.

Typical users may include:

- Unreal Engine developers
- Game developers
- AI-assisted programmers
- Technical artists
- Solo developers
- Small development teams
- Developers using Codex
- Developers using Nwiro
- Users who want one interface for multiple development systems

============================================================
6. FIRST LAUNCH
============================================================

On first launch, ENGINE NEXUS opens into its setup experience.

The setup process is used to:

- Detect supported integrations
- Detect required dependencies
- Determine which selected systems are ready
- Install supported missing dependencies
- Configure selected integrations
- Confirm that at least one AI provider is ready before setup is completed

ENGINE NEXUS separates several important states.

An integration may be:

- Selected
- Installed / Detected
- Configured / Authenticated
- Verified Ready
- Enabled / Active

These states are not the same thing.

For example, an integration may be installed but not authenticated, or authenticated but not currently enabled.


============================================================
7. DEPENDENCY SETUP
============================================================

ENGINE NEXUS includes dependency detection and setup support.

During setup, the application checks whether required software is available.

For Codex, the current dependency chain may include:

Node.js / npm
↓
Codex
↓
Codex authentication
↓
READY

If Node.js or npm is missing, ENGINE NEXUS can bootstrap Node.js first.

After Node.js is installed, ENGINE NEXUS refreshes dependency detection and attempts to detect npm.

Once npm is available, ENGINE NEXUS can install Codex.

If an installation fails, ENGINE NEXUS is designed to display an installation failure message explaining what failed and, where available, why.

IMPORTANT

During normal ENGINE NEXUS setup, users should avoid manually installing missing dependencies unless troubleshooting instructions specifically require it.

The purpose of the setup flow is to test and use ENGINE NEXUS dependency management itself.


============================================================
8. DOWNLOAD ALL DEPENDENCIES
============================================================

The dependency setup page may provide a Download All Dependencies action.

This action attempts to install supported missing dependencies required by the selected integrations.

Typical behaviour:

1. ENGINE NEXUS scans the selected integrations.
2. Missing dependencies are identified.
3. Download All Dependencies is selected.
4. ENGINE NEXUS installs supported dependency prerequisites.
5. ENGINE NEXUS refreshes detection.
6. Remaining supported dependencies are installed.
7. Readiness is checked again.

If a dependency cannot be installed automatically, ENGINE NEXUS should report the failure rather than silently pretending everything worked. Humanity has suffered enough software that does that already.


============================================================
9. CODEX INTEGRATION
============================================================

ENGINE NEXUS currently includes Codex integration.

Codex is used as an AI development provider inside ENGINE NEXUS.

Typical Codex setup:

1. Select Codex during setup.
2. Allow ENGINE NEXUS to detect Codex.
3. If required, install missing Node.js / npm.
4. Allow ENGINE NEXUS to install Codex.
5. Complete Codex authentication.
6. Confirm Codex readiness.
7. Open the AI Work Room.
8. Send a test message.

A successful test confirms that Codex can respond inside ENGINE NEXUS.

ENGINE NEXUS is designed to replace the need to use the normal Codex CLI for everyday work, while the CLI may still be useful for fallback or debugging.


============================================================
10. NWIRO INTEGRATION
============================================================

ENGINE NEXUS includes support for Nwiro integration.

Nwiro is intended to provide connected development functionality, including workflows involving supported external development systems such as Unreal Engine.

Availability and readiness depend on the version of Nwiro installed and the configuration present on the machine.

ENGINE NEXUS treats Nwiro as a separate integration with its own detection, configuration, readiness, and active state.


============================================================
11. UNREAL ENGINE INTEGRATION
============================================================

ENGINE NEXUS includes Unreal Engine integration support.

The Unreal integration is intended for workflows where ENGINE NEXUS is used alongside Unreal Engine development.

ENGINE NEXUS may detect supported Unreal installations or projects depending on the integration configuration.

The integration layer is designed so Unreal Engine is not hard-coded as the only supported game engine. The architecture is modular so additional engines may be added in future releases.


============================================================
12. HOME
============================================================

After initial setup has been completed, the HOME area acts as the main application dashboard.

The HOME area is intended to provide a simpler overview rather than duplicating every specialist page.

The HOME area includes two main views:

BASE

The Base view is the main launched dashboard and provides general application information and status.

STATS

The Stats view provides task-manager-style system information, including supported local statistics such as:

- CPU
- Memory
- Disk
- Temperature where available

Detailed specialist information remains on the relevant dedicated pages.


============================================================
13. AI / WORK ROOM
============================================================

The AI area includes the Work Room.

The Work Room is the primary place for interacting with supported AI providers.

It is designed as a hybrid AI chat and development interface rather than a simple chat box.

Supported context visibility modes include:

CHAT

Focuses on conversational AI interaction.

TASK

Focuses on the task being performed.

CODE

Focuses on code output and terminal-style development work.

ALL CONTEXT

Shows the broadest supported context for the current AI interaction.

The selected mode controls how much of the working context is emphasized or displayed.

The Work Room is intended to become the main daily AI development environment inside ENGINE NEXUS.


============================================================
14. CODE-FOCUSED MODE
============================================================

When using code-focused work, ENGINE NEXUS is designed to provide a terminal-oriented development view.

The code-focused experience is intended to resemble the practical clarity of a development terminal rather than a decorative chat interface.

Where supported, unrelated visual activity may be reduced while the code or terminal-focused view is active.

============================================================

ENGINE NEXUS includes application settings for supported configuration and accessibility options.

============================================================
21. SESSION RESTORE
============================================================

ENGINE NEXUS stores supported user configuration and session state.

After setup has been completed, the application is designed to remember relevant choices and restore a usable state on future launches.

On startup, ENGINE NEXUS may continue using the last known session/configuration or allow the user to reconfigure supported systems.

This helps avoid repeating the complete setup process every time the application is opened.


============================================================
22. READINESS STATES
============================================================

ENGINE NEXUS distinguishes between several readiness concepts.

SELECTED

The user has chosen the integration.

INSTALLED / DETECTED

ENGINE NEXUS can detect the required software.

CONFIGURED / AUTHENTICATED

The integration has the required configuration or login state.

VERIFIED READY

ENGINE NEXUS has confirmed that the integration meets its readiness checks.

ENABLED / ACTIVE

The integration is currently enabled for use.

A green or ready state should only be treated as meaningful when the required readiness conditions have actually been verified.


============================================================
23. TROUBLESHOOTING
============================================================

GENERAL RULE

If setup fails, stop at the first failure and record what ENGINE NEXUS reports.

Do not install random software or change unrelated system settings before understanding the failure.

This is especially important during the public test beta because failure information helps identify genuine ENGINE NEXUS problems.


------------------------------------------------------------
CODEx DOES NOT INSTALL
------------------------------------------------------------

Check whether ENGINE NEXUS reports:

- Node.js missing
- npm missing
- Codex installation failure
- Authentication required

If Node.js / npm is missing, use ENGINE NEXUS dependency installation first.

After installation, allow ENGINE NEXUS to rescan.


------------------------------------------------------------
CODEX IS INSTALLED BUT NOT READY
------------------------------------------------------------

Possible causes:

- Authentication is incomplete
- Codex cannot be detected
- The environment has not refreshed
- A required dependency is unavailable

Complete authentication and then refresh or restart ENGINE NEXUS if required.


------------------------------------------------------------
WINDOWS SMARTSCREEN WARNING
------------------------------------------------------------

Version 1.0.0 is unsigned.

A SmartScreen warning does not automatically mean the installer is malicious.

Users should verify that:

- The installer came from the official DEFIXAS GitHub release
- The filename matches
- The SHA-256 hash matches the official release checksum


------------------------------------------------------------
AN INTEGRATION SHOWS AS UNAVAILABLE
------------------------------------------------------------

Some integrations shown by ENGINE NEXUS may be planned, disabled, unsupported on the current system, or unavailable in version 1.0.0.

Only modules marked available during Setup are supported in the current release.


------------------------------------------------------------
SYSTEM STATISTIC IS MISSING
------------------------------------------------------------

Some statistics depend on hardware, drivers, or Windows reporting capabilities.

If a temperature or other metric is unavailable, this may reflect the machine rather than an application fault.

25. CLEAN-PC TEST PROCEDURE
============================================================

For testers evaluating automatic dependency setup:

1. Install ENGINE NEXUS.
2. Launch ENGINE NEXUS.
3. Select Codex.
4. Allow ENGINE NEXUS to detect missing dependencies.
5. Do not manually install Node.js, npm, or Codex.
6. Use Download All Dependencies.
7. Allow ENGINE NEXUS to install supported prerequisites.
8. Complete Codex authentication.
9. Open the Work Room.
10. Send a simple test message such as:

hi

11. Confirm Codex responds.
12. Close ENGINE NEXUS.
13. Launch ENGINE NEXUS again.
14. Confirm the configuration/session remains usable.

If any step fails:

STOP.

Record the first failure before manually changing the machine.
